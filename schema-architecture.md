This Spring Boot application is built on a flexible architecture that combines Thymeleaf-rendered web dashboards—such as those for administrators and doctors—with REST APIs serving various frontend modules and mobile clients. When requests enter the system, they are handled by either MVC or REST controllers, which then delegate business logic and workflow coordination to a centralized service layer.
To manage data persistence, the application utilizes a dual-database setup. MySQL stores structured relational data like users, doctors, and appointments using Spring Data JPA entities, while MongoDB manages flexible, document-based prescription records through Spring Data MongoDB models. This clean separation between the presentation, service, and repository layers ensures high maintainability and robust support for both traditional web views and modern API-driven interactions.

1. Users interact with the system through two main channels: Thymeleaf-based web dashboards (which render traditional HTML pages on the server for browsers) or REST API clients like mobile apps and frontend modules that communicate via HTTP and handle JSON responses.
2. When a user action triggers a request, it is routed to the appropriate backend controller based on the URL path and HTTP method. Thymeleaf Controllers handle server-rendered views, whereas REST Controllers process API inputs and return JSON formats while enforcing request validation and coordination.
3. Controllers delegate business logic to the service layer, which acts as the core of the backend. This layer enforces business rules, performs validations, and coordinates complex workflows across multiple entities while maintaining a clean separation from data access and controller logic.
4. The service layer communicates with repositories to handle data access operations. This includes MySQL Repositories (using Spring Data JPA for structured relational data like users, doctors, and appointments) and MongoDB Repositories (using Spring Data MongoDB for document-based records like prescriptions).
5. Each repository interfaces directly with its respective database engine. MySQL stores core entities requiring a normalized relational schema, while MongoDB accommodates flexible, nested, and rapidly evolving data structures such as prescriptions.
6. Data retrieved from the databases is mapped into application-compatible Java model classes. Relational data from MySQL is converted into JPA entities annotated with @Entity, while data from MongoDB is mapped into document objects annotated with @Document.
7. The bound models complete the request-response cycle. In MVC flows, they are passed to Thymeleaf templates to render dynamic HTML pages, while in REST flows, they (or transformed DTOs) are serialized into JSON and sent back to the client via HTTP responses.
